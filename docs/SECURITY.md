# Безопасность V2Scale

Что именно защищено, что проверено и где остаются ограничения. Документ описывает фактическое
состояние кода, а не намерения. Проверки выполнены на Nothing Phone (Android 16) со сборкой из этого
репозитория; где проверка была кодом или тестом, это указано.

## Модель угроз

Защищаем от: провайдера и локальной сети (трафик и DNS), других приложений на этом же телефоне,
утечки секретов через резервные копии. Не защищаем от: компрометации самого телефона (root,
вредоносная сборка), компрометации вашего Headscale/прокси-сервера, анализа трафика по метаданным
(см. раздел «Что видит сеть»).

## Что защищено и как это проверено

| Свойство | Как достигается | Проверка |
| -------- | --------------- | -------- |
| Имена tailnet не уходят в публичный DNS | Системный DNS (UDP/TCP 53) перехватывается Xray (`-> dns-out`), домены tailnet отвечает сам узел через DNS-мост (`QueryDNS`), имена вне tailnet мост отклоняет (`REFUSED`) | Логи устройства: запросы идут `[socks -> dns-out]`, затем `[dns-module -> tailnet]`; тесты `dnsbridge_test.go` |
| DNS-over-TLS не обходит перехват | При MagicDNS и доменах правило `tcp:853 -> block`: Android не проходит валидацию Private DNS и откатывается на обычный DNS | Лог устройства: `taking detour [block] for [tcp:1.1.1.1:853]`; `dumpsys connectivity` до/после |
| Узел не отдаёт имя системному резолверу | `Node.DialContext` сам резолвит имя (static, extra_records, MagicDNS) и **отказывает** для имён вне tailnet. Раньше tsnet при неизвестном имени уходил в системный резолвер процесса, а приложение исключено из VPN, то есть запрос шёл бы к DNS провайдера в открытом виде | Тесты `TestNodeResolvesExtraRecordsAndStaticHosts` (имя вне tailnet даёт `ErrNotTailnetName`, а не `net.DNSError`) |
| Отказ закрытый | Правило `-> tailnet` без работающего узла даёт ошибку соединения, а не уход в `direct` | Тест Фазы 2 (см. DEVLOG): правило на тег без обработчика обрывает соединение, а не уходит в `direct` |
| Локальный SOCKS не открыт для чужих приложений | Порт `127.0.0.1:10808` доступен любому приложению телефона. Пока tailnet включён и вы не задали свои логин и пароль, приложение само генерирует случайные (24 символа, `SecureRandom`, в приватных настройках) и использует их в Xray, туннеле и проверках | На устройстве: рукопожатие без аутентификации даёт `05 ff` (раньше `05 00`, и `CONNECT` в tailnet проходил); hev без отказов, Nextcloud и проверка сервера работают. Тесты `LocalProxyAuthTest` |
| Ключ узла не попадает в резервные копии | `files/tailnet` исключён из облачной копии и переноса на другое устройство (`data_extraction_rules.xml`, `backup_rules.xml`) | Код манифеста; клон узла на другом телефоне иначе дал бы чужую личность в сети |
| Разовый ключ входа не хранится | Стирается из настроек, как только узел вошёл в `running` | Код `TailnetRuntime`; на устройстве поле ключа пусто после входа узла |
| Логи Tailscale не уходят наружу | `TS_NO_LOGS_NO_SUPPORT`, каталоги состояния в приватном каталоге | Код `prepareEnv` |
| Нет второго VPN и локальных портов tailnet | tsnet работает в userspace (netstack) в том же процессе; для tailnet нет слушающих сокетов | Код, `ss`/`/proc/net/tcp` |
| IPv6 не обходит туннель | По умолчанию IPv6 выключен, маршрут `::/0 -> unreachable` в VPN | `dumpsys connectivity` |

## Что видит сеть (метаданные)

Приложение исключено из VPN, чтобы его собственные сокеты не заходили обратно в туннель. Поэтому
провайдер и локальная сеть **видят** (без содержимого):

- соединение с сервером управления (по вашему адресу, через прокси или i2pd, если они настроены);
- UDP к серверам DERP и STUN и WireGuard-пакеты к пирам (адреса пиров при прямом соединении);
- соединение Xray с вашим прокси-сервером и DNS-запрос его имени при сборке конфигурации
  (унаследовано от V2RayNG);
- сам факт, что телефон использует Tailscale/Headscale.

Содержимое трафика tailnet зашифровано WireGuard, содержимое остального трафика - вашим прокси.

## Ограничения (честно)

1. **Приложения со своим DNS-over-HTTPS** (например, Firefox с включённым DoH, Chrome «Безопасный DNS»,
   приложения с вшитым резолвером) обходят системный DNS: запрос уходит их провайдеру через ваш прокси,
   и **имена вашего tailnet раскрываются ему**, а сами имена не резолвятся. Отключайте DoH в таких
   приложениях. DoT на порт 853 блокируется только пока включены MagicDNS и домены.
2. **«Строгий» Private DNS** с вашим именем хоста сделает имена tailnet недоступными (его запросы
   блокируются правилом 853). Утечки нет, но и работы нет; используйте «Автоматически» или «Выкл».
3. **Нет аварийного выключателя.** Если процесс демона завершён системой (мы это наблюдали), VPN
   пропадает, и трафик идёт напрямую, пока вы не запустите VPN снова (как и в upstream). Включите
   системные «Постоянный VPN» и «Блокировать соединения без VPN» (в настройках есть пункт
   «System VPN settings»).
4. **Локальный прокси без tailnet.** При выключенном tailnet поведение как в upstream: SOCKS без пароля,
   если вы его не задали. Задайте логин и пароль в настройках, если не используете прокси вручную.
5. **Секреты на диске не шифруются отдельно.** Ключ узла лежит в приватном каталоге приложения
   (шифруется шифрованием файлов Android, но не ключом Keystore). Для устройства с root или физическим
   доступом после разблокировки этого недостаточно. Обёртка ключом Keystore - в планах.
6. **Логи.** В логах Android на уровне `warning` видны строки маршрутизации с адресами назначения
   (доступны только по `adb` и в отчётах об ошибках). Уровень логов `none` их убирает.
7. **Унаследовано от V2RayNG:** `allowBackup` включён для остальных данных приложения (профили прокси
   и т.д.), разрешён cleartext-трафик (нужен для `http://127.0.0.1:...` у control через i2pd),
   несколько экспортируемых компонентов (главная страница, виджет, плитка, схема URL).
8. **Зависимости** закреплены (`libv2scale/go.mod`: Xray-core, Tailscale) и обновляются вручную.
   Следите за обновлениями безопасности Tailscale и Xray-core.

## Как проверить самому

```bash
# 1. Локальный SOCKS не пускает посторонних (ожидаем 05 ff, не 05 00):
adb shell "printf '\x05\x01\x00' | timeout 3 nc 127.0.0.1 10808 | od -An -tx1"

# 2. Системный DNS у VPN и состояние Private DNS:
adb shell dumpsys connectivity | grep -E "DnsAddresses|UsePrivateDns"

# 3. DNS идёт в ядро, а не мимо него (запросы видны как dns-out / dns-module):
adb logcat -d | grep -E "dns-out|dns-module|\[block\] for \[tcp:.*:853\]"

# 4. Имя вне tailnet не резолвится узлом: (юнит-тесты)
cd libv2scale && go test ./tailnet -race -run 'NodeResolves|DNSBridge'
```
