## 2026-10-18 - Фаза 2: UDP, DNS-мост, статусы, интеграция в CoreController

- **UDP** в `tailnet.Handler`: подключённый UDP на поток (`Dial("udp")`), границы датаграмм
  сохраняются (тест 1/17/512/1200 байт), простой потока 2 минуты, без full-cone.
- **Счётчики трафика** `outbound>>>tailnet>>>traffic>>>uplink|downlink` (учитывают флаги политики
  `statsOutboundUplink/Downlink`, как у встроенных outbound); тест сверяет с отправленным объёмом.
- **DNS.** Пробы показали, что `100.100.100.100:53` по сети из tsnet пересылает запросы наружу
  (утечка), хотя локальный API отвечает правильно. Реализован **DNS-мост**: на запросы к MagicDNS-адресу
  (UDP и TCP) обработчик отвечает сам через `Node.QueryDNS`; чужие имена получают `REFUSED`,
  сбой резолвера - `SERVFAIL`, мусор - `FORMERR`. `nameTable` теперь знает зоны tailnet (по
  `DNS.Domains`, `extra_records`, `hosts`). Тесты: Xray DNS-модуль с upstream `100.100.100.100` и
  `tcp://100.100.100.100` резолвит пира, `extra_records` типа `A` внутри и вне домена tailnet.
- **Статусы и вход.** `Node.Status` отдаёт `needs-login` со ссылкой; тесты интерактивного входа
  (`CompleteAuth`), входа по ключу и отказа при неверном ключе. `WaitUp` дожидается применения DNS.
- **CoreController.** `SetTailnetConfig(json)`, `TailnetStatus()` (JSON), запуск узла в `StartLoop`
  до старта ядра, остановка в `StopLoop`; без конфигурации поведение прежнее, правило на тег
  `tailnet` падает безопасно. В `libv2ray_main.go` две точки вызова, остальное в новом файле.
- **Тестовая среда.** Общий пакет `internal/testenv` (control, DERP/STUN, узлы, эхо) для тестов

## 2026-10-18 - Смена сети Wi-Fi <-> LTE

Найдено и исправлено три причины потери имён tailnet после смены сети:

1. `NetworkMonitor` перезапускает ядро (`reloadCore`), а вместе с ним пересоздавался узел Tailscale:
   кэш имён пуст, control через i2p поднимается 60+ с. Теперь `CoreController.StopLoopForReload()`
   оставляет узел работать; `startTailnet` переиспользует его, если не изменилась идентичность
   конфигурации (`Config.Identity()`, без auth key, который стирается после регистрации).
   `StopLoop` по-прежнему освобождает узел. Тест `TestReloadKeepsTailnetNode`.
2. После смены сети узел отдаёт DNS-конфигурацию с пропавшими частями; `nameTable` затирал кэш и
   отвечал «не имя tailnet». Теперь пустой список трактуется как «неизвестно», записи и домены
   сохраняются (тесты на полностью пустой и частичный конфиг).
3. Пока резолвер узла не готов, A/AAAA для известных имён (static hosts и extra_records) отвечаются из
   кэша авторитетным ответом (`synthesizeAnswer`), ничего не уходит в публичный DNS.

Дополнительно: для tailnet-сервера в DNS Xray выставлен `disableCache`, иначе кэшированный
отказ делал имя нерезолвимым надолго. Результат на телефоне: имя резолвится на всех этапах
(старт, LTE, возврат на Wi-Fi), страница Nextcloud открывается после перехода, без простоя.

Открыто: старт узла через i2p занимает около минуты (имена в это время недоступны), режим полёта,
Doze и автоперезапуск не проверены.

## 2026-10-18 - Calino по tailnet и тест подключения на главной

- **Calino**: календарь `Personal` (Nextcloud CalDAV) синхронизируется через tailnet, но при синхронизации
  Calino первым открывает соединение на порт **80** (`100.64.0.2:80`), а ACL для `tag:v2scale` разрешает

  (Caddy отвечает редиректом на 443) или указать в Calino адрес с `https://`.
- Первое соединение после подъёма узла занимает около 5 с (установка пути, как и с Mac), следующие -
  миллисекунды.
- **Тест подключения на главной**: под статусом сервера строка `Tailnet: ...`, нажатие запускает тест
