# Установка и настройка V2Scale с нуля

Инструкция от пустого Mac и самописного Headscale до работающего tailnet на телефоне. Все адреса,
имена и ключи ниже - примеры, подставьте свои. Секреты (ключи авторизации) нигде не сохраняйте.

Что получится: приложение V2Scale (форк V2RayNG) держит обычный VPN с вашим прокси (VLESS и т.д.) и
заодно встроенный узел Tailscale/Headscale. Имена и адреса вашего tailnet открываются из любых
приложений телефона, а остальной трафик идёт как в V2RayNG.

Что не входит в первую версию: exit node, subnet routing (см. [DECISIONS.md](DECISIONS.md)).

## 1. Что нужно заранее

- Телефон на Android 7+ (проверено на Nothing Phone, Android 16), `arm64-v8a`.
- Сервер управления: свой Headscale (или аккаунт Tailscale). Пример ниже для Headscale 0.26+.
- Рабочий прокси для V2RayNG-части (VLESS/Reality и т.п.), как и для обычного V2RayNG.
- Mac (или Linux) для сборки, `adb` и телефон с отладкой по USB.

## 2. Сервер: Headscale

### 2.1 ACL с тегом для телефона

Телефон удобно регистрировать с тегом, тогда правило ACL не привязано к IP узла. В файле политики
(пример `config/acl.hujson`):

```jsonc
{
  "tagOwners": { "tag:v2scale": ["your-user@"] },
  "hosts": { "my-server": "100.64.0.2" },
  "acls": [
    {
      "action": "accept",
      "src": ["tag:v2scale"],
      "dst": ["my-server:443"]
    }
  ]
}
```

Перечислите в `dst` все порты, к которым приложения будут ходить. Всё, что не разрешено, **молча
отбрасывается**: клиент видит не отказ, а зависание до таймаута.

Типичный случай: приложение сначала пробует `http://` на порту 80 и только потом `https://`. Тогда
нужно разрешить и 80 (веб-сервер ответит редиректом на 443), либо указывать в приложении адрес с
`https://`:

```jsonc
"dst": ["my-server:443", "my-server:80"]
```

Применение: сохраните файл и перезапустите Headscale (`docker compose restart headscale`). Заодно
это заставляет серверы пересчитать пакетный фильтр: **после регистрации нового узла с тегом
перезапускайте Headscale**, иначе целевой узел может некоторое время отбрасывать его пакеты.

### 2.2 Имена внутри tailnet (необязательно)

Имена вида `service.example.net` можно отдать через `extra_records` Headscale (запись типа `A`). V2Scale
разрешает их сам, ничего не уходит в публичный DNS. Домен затем указывается в настройках Tailnet
(раздел 4).

### 2.3 Ключ для первого входа

```bash
headscale users list                       # узнать числовой ID пользователя
headscale preauthkeys create --user <ID> --tags tag:v2scale --expiration 1h
```

Для одноразового входа ключ **не** делайте `--reusable`. Ключ действует до регистрации узла, после
неё приложение стирает его из своих настроек. Если команда принимает другие флаги, см.
`headscale preauthkeys create --help`.

Вместо ключа можно войти по ссылке: оставьте поле ключа пустым, приложение покажет ссылку, а на сервере
выполните `headscale nodes register --user <имя> --key <ключ из ссылки>`.

### 2.4 Доступ к серверу управления с телефона

Если Headscale доступен с интернета по HTTPS, укажите его адрес. Если нет публичного IP, одно из
решений - i2pd на телефоне (клиентский туннель `http://127.0.0.1:7080` к скрытому сервису Headscale).
Тогда адрес сервера управления - `http://127.0.0.1:7080`, а установка соединения занимает до минуты
(i2p строит туннели). Прокси для control-канала указывается отдельно, если туннель торчит как HTTP-прокси.

## 3. Сборка и установка

Нужные инструменты и как их удалить: [INSTALLED-TOOLS.md](INSTALLED-TOOLS.md) (JDK 21, Android SDK
platform 37, build-tools 37.0.0, NDK 30.0.16248370, Go, `gomobile`).

```bash
git clone --recurse-submodules git@github.com:Ezhkin-Kot/v2scale.git
cd v2scale
bash scripts/build-hevtun.sh      # hev-socks5-tunnel (нативная часть, один раз)
bash scripts/build-core.sh        # Go-ядро: Xray + Tailscale -> libv2ray.aar (~25 МБ)
bash scripts/build-app.sh         # APK; по умолчанию только arm64-v8a
adb install -r V2rayNG/app/build/outputs/apk/playstore/debug/v2rayNG_*_arm64-v8a.apk
```

Приложение ставится рядом с V2RayNG (`applicationId` `org.v2scale.android`), настройки у них
раздельные. Версию ядра и Tailscale задаёт `libv2scale/go.mod`, обновлять её нужно сознательно.

Проверки: `cd libv2scale && go test ./... -race`, `cd V2rayNG && ./gradlew :app:testPlaystoreDebugUnitTest`.

## 4. Настройка приложения

1. Добавьте профиль прокси как в обычном V2RayNG (подписка, ссылка, QR) и выберите его.
2. **Настройки -> VPN settings -> Enable local DNS**: включите. Без этого системные DNS-запросы не
   доходят до DNS-модуля Xray, и имена tailnet не резолвятся.
3. **Настройки -> Tailnet** (глобальная страница, не зависит от профиля):

| Поле | Значение |
| ---- | -------- |
| Enable Tailnet | включить |
| Control server URL | адрес Headscale, например `https://headscale.example.net` |
| Auth key | ключ из п. 2.3 (только для первого входа), либо пусто для входа по ссылке |
| Node name | имя узла в tailnet, например `my-phone` |
| Proxy for the control connection | необязательно; HTTP-прокси только для связи с сервером управления |
| Tailnet domains | домены (по одному в строке), имена под которыми резолвятся и открываются через tailnet |
| Resolve tailnet names | оставить включённым |
| Subnets routed into the tailnet | `100.64.0.0/10` есть всегда, добавьте свои подсети при необходимости |
| Connection test target | необязательно, `host:port` для теста на главной (иначе пинг пира) |

4. Нажмите галочку (сохранить), запустите VPN. Подключение узла видно на странице Tailnet и в
   строке под статусом на главной: `Tailnet: connected 100.64.x.x. Tap to test.`
5. Первый запуск и запуск через i2p занимают до минуты, потому что узлу нужна карта сети с сервера
   управления.

Нажатие на строку `Tailnet:` запускает тест подключения. Без цели это пинг доступного пира
(`Tailnet: 6 ms, direct (my-mac)`), с целью - TCP-соединение через узел, как у обычного трафика
(проверяет DNS и ACL).

## 5. Как это работает с точки зрения безопасности

- Приложение исключено из VPN, поэтому сокеты узла (WireGuard, control, DERP) не попадают обратно в
  туннель. Локальных слушающих портов для tailnet нет.
- Логи Tailscale наружу не отправляются. Ключ узла хранится в приватном каталоге приложения.
- Чтобы системные запросы DNS-over-TLS (порт 853) не обходили DNS-модуль, при включённых MagicDNS и
  доменах приложение блокирует TCP/853 в туннеле; Android откатывается на обычный DNS, который
  перехватывает ядро. Ограничение: «строгий» Private DNS с вашим именем хоста останется нерабочим.

## 6. Типичные проблемы

| Симптом | Причина и что делать |
| ------- | -------------------- |
| `Connecting…` долго | Control-канал недоступен или медленный (например, i2pd: `Firewalled`, низкий процент туннелей). Проверьте `/health` сервера через ваш адрес, подождите. После первого подъёма узел переживает смену сети |
| Имя не открывается, `ping` говорит `unknown host` | Включён ли Enable local DNS; подождите подъёма узла; тот ли домен указан на странице Tailnet |
| Имя резолвится, страница висит | ACL не разрешает порт/узел; на сервере перезапустите Headscale (новый тегированный узел) |
| Приложение (например, CalDAV) долго синхронизируется или падает | Оно пробует порт 80 или другой запрещённый порт: разрешите его в ACL или укажите `https://` |
| Firefox спрашивает разрешение «устройства поблизости» | Это Android 16 при обращении к 100.64.0.0/10. Отказ не мешает маршрутизации |
| После обновления приложения VPN выключен | Установка перезапускает процесс: запустите VPN заново |

## 7. Отзыв ключей и удаление узлов

```bash
headscale preauthkeys list
headscale preauthkeys expire --id <ID>      # отозвать ключ (синтаксис зависит от версии, см. --help)
headscale nodes list
headscale nodes delete --identifier <ID>    # удалить узел
```

Тестовые и неиспользуемые узлы лучше удалять, а их записи `hosts` и правила в ACL убирать. Состояние
узла на телефоне лежит в приватном каталоге приложения (`files/tailnet`), стирается очисткой данных
приложения.
