## Открытые вопросы (нужно решение пользователя)

1. **Идентификатор приложения и GitHub-путь.** Когда появится удалённый репозиторий,
   выберем `applicationId`, модульный путь Go и ссылки в документации.
2. **Тестовая инфраструктура.** Для прогонов против настоящего Headscale понадобится отдельный
   тестовый pre-auth ключ и узел (не рабочий). Герметичные тесты (`testcontrol`) идут без него.
3. **Обработка Private DNS (Фаза 4).** Если окажется, что надёжный путь DNS требует
   отключить или заблокировать DoT на уровне VPN, готовы ли вы принять это ограничение, пока
   включён V2Scale?

## Процедура синхронизации с upstream

```bash
git fetch upstream
git merge upstream/master          # в ветке master; конфликты разбираем вручную
git push origin master
```

GitHub-репозиторий `Ezhkin-Kot/v2scale` создан как fork (кнопка Sync fork тоже подойдёт, но
после неё нужно `git pull`).

Правило: изменения в файлах upstream делаем малыми, логически завершёнными коммитами;
новую функциональность по возможности кладём в новые файлы (`libv2scale/tailnet/`,
`ui/.../tailnet/`), чтобы конфликты слияния были локальными. После слияния прогоняем
`go test ./...` в `libv2scale` и смоук-сборку.
